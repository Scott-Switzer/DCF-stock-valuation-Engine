## 3. Differences between sources

- **Yahoo current snapshot vs SEC FY2025:** revenue, EBIT, net income, D&A, CapEx, tax rate, cash and long-term debt are identical. Yahoo's short-term debt of 20,329 equals CP + current LTD, which is correct. Yahoo's NWC matches the app definition. Yahoo's output intrinsic value equals the independent value to 1e-6.
- **SEC loader (opt-in) vs full SEC data:** the loader leaves NWC null for every period because `CommercialPaper` and `DebtCurrent` are not mapped. The short-term debt field is null, so current LTD of 12,350 is dropped. `parse_document` rejects the document with an explicit message ("nwc requires a typed JSON number"). This is a visible block, not a silent error, but the SEC path cannot value Apple.
- **Share basis:** market-cap weights use about 14,773M shares, while per-share value uses 15,005M weighted diluted shares. Both are documented; the choice moves value by about 2.6%.
- **Dates:** Yahoo labels fiscal years as 09-30 while SEC period ends are 09-27 and 09-28. Labels only.

## 4. MRX diagnosis

**Reproduced:** the current-date Yahoo load fails with "Yahoo financial snapshot failed validation: minority_interest must be at least 0."

**Trace:**
1. Raw Yahoo `annualMinorityInterest` for 2025-12-31 is −200,000 USD.
2. `yahoo_provider.load_yahoo` takes that value directly (`v("MinorityInterest", True)`) with no sign check and no fallback. The fallback (total equity − stockholders' equity) runs only when the field is absent.
3. `TotalEquityGrossMinorityInterest` is 1,263.6M and `StockholdersEquity` is 1,263.8M. Their difference is the −0.2M. So the source itself reports a −$0.2M noncontrolling interest, or a rounding artifact. I cannot tell which from Yahoo alone; the filing would settle it, and I did not retrieve it.
4. `dcf_loader.parse_document` enforces nonnegative bridge fields, so it raises.

The mapping is correct. Nothing was zero-filled or made absolute, and the batch's constraints hold.

**Materiality:** −$0.2M against common equity of $1,263.8M is 0.02%. The model would subtract it, so the equity bridge would add $0.2M. Immaterial.

**Scope defect:** `load_yahoo` runs `parse_document` for every method (DCF, DDM, relative and peers). So this immaterial item blocks P/E and P/B, which use neither minority interest nor the EV bridge. The gate is too broad.

**Classification:** MRX is a financial-services firm (brokerage, clearing and market-making). I could not confirm this in this run: the SEC directory returned 403, web search was unavailable, and Yahoo's sector field is empty, so the eligibility gate cannot fire. Financial-firm treatment currently depends on the user's checkbox.

**Method suitability:**
- FCFF DCF: not appropriate. Funding debt and client balances are operating, so the EV bridge has no economic meaning.
- P/E and P/B: appropriate in principle. Raw inputs exist: common net income FY25 $293.9M, diluted shares 71.7M (EPS about $4.10), common equity $1,263.8M (book value about $17.62 per share).
- Residual income: appropriate, but needs a cost of equity and a forecast. The cost of equity needs a verified beta and market inputs that this run did not complete.

**Recommended fix (not implemented; needs a design decision):** scope the minority-interest check to methods that use the EV bridge, or accept a signed noncontrolling interest with explicit provenance. Do not use `abs()` or zero. A new bank or broker model is out of scope for this batch.
