# Production monitoring and recovery

The existing daily GitHub Actions Public Worker smoke workflow now checks health/readiness, provider metadata, ticker search, synthetic preview/export, real AAPL loading twice, market/annual freshness, independent real-company DCF arithmetic and a formula-driven XLSX archive. Preview and exports do not save valuations or research; no user account is accessed. Logs contain public source names, ages, timings and check status only.

Run `uv run python scripts/smoke_public.py --require-ppe --real-ticker AAPL --expected-commit FULL_SHA --output smoke.json` after deployment. The expected-commit gate requires the embedded clean Git SHA. `/health` also reports a deterministic public asset SHA256. Build metadata is generated by the bundle script; it does not expose environment variables or credentials. Stale generated Python modules from other branches are removed before bundling.

Default freshness budgets are seven calendar days for market price and 550 days for the latest annual period; these are operational alerts, not proof of filing accuracy or point-in-time availability. Override with `--max-price-age` and `--max-financial-age`. The response budget is 30 seconds per request (`--max-response-seconds`); request timeout is configurable separately. Compare the first and repeated company timings across retained workflow artifacts, but do not infer cache hit rates from latency alone. External upstream failures remain distinct from deterministic test failures. One AAPL check does not prove the entire company universe is healthy.

The independent calculator shares explicit forecast assumptions and reported inputs, but imports no production model. It checks FCFF, terminal value, enterprise/common equity, today's value and the 12-month scenario. Workbook monitoring checks delivery, ZIP integrity and formula presence; deterministic reconciliation tests separately check workbook arithmetic. This is not independent SEC source reconciliation.

Before deployment retain the prior Worker version and exact Git SHA. Use `--keep-vars`, preserve bindings, apply only reviewed additive migrations and verify no pending migration remains. If critical production checks fail, roll back to the saved prior Worker version with Wrangler; retain additive D1 tables. Never restore a database over new user data as a deployment shortcut.

## Email delivery dependency

The inspected Worker has only the RECORD_SALT secret and no email-sending binding. There is no verified sender/domain or delivery credential configured for this application. Existing accounts remain unverified and have no recovery email. Completing verification/reset requires a chosen transactional delivery service, a verified sender/domain and a server-only sending credential or Cloudflare email binding. Tokens must then be hashed, expiring and single-use, with generic request responses, resend/request throttles and session revocation on reset. Do not claim delivery or activate a nonfunctional reset screen before real delivery and token lifecycle acceptance pass.
